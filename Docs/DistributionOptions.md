# 配布方式の比較と推奨

現在の「SDF Make Supporter」の規模（Python/CustomTkinter製の小規模ツール、VRChatクリエイター向け）を考慮し、現実的な配布方式を比較しました。

結論から述べると、**「2. シングルEXE + Zip配布」** が最もコスト対効果が高くおすすめです。

## 比較表

| 方式 | ユーザーの手間 | 開発者の保守コスト | 特徴 | おすすめ度 |
| :--- | :--- | :--- | :--- | :--- |
| **1. シングルEXEのみ** | 低 | **最低** | ファイル1つを渡すだけ。シンプル。 | ★★★★☆ |
| **2. Zip配布 (EXE+α)** | 低 | **低** | READMEやライセンスを含められる。 | **★★★★★** |
| **3. インーラー (Setup.exe)** | 中 (インストール作業) | 中 | プロっぽい挙動。ショートカット作成可。 | ★★☆☆☆ |
| **4. Pythonパッケージ (pip)** | **高** (環境構築必要) | 高 | エンジニア向け。一般ユーザーには不向き。 | ★☆☆☆☆ |

---

## 各方式の詳細

### 1. シングルEXEのみ (Standalone EXE)
現状の `PyInstaller --onefile` で生成された `.exe` ファイルをそのまま配布する方法です。

- **メリット**:
  - ユーザーはダウンロードしてダブルクリックするだけ。
  - 開発者はビルド後、そのファイルをアップロードするだけ。
- **デメリット**:
  - 説明書(README)やライセンスファイルを同梱しにくい（アプリ内に組み込む必要がある）。
  - 設定ファイル等が生成される場合、EXEと同じ場所に散らばる可能性がある。
- **保守性**:
  - 非常に高い。追加のツール学習コストゼロ。

### 2. Zip配布 (EXE + README) 【推奨】
ビルドしたEXEと、`README.txt` などをフォルダに入れ、Zip圧縮して配布する方法です。

- **構成イメージ**:
  ```text
  SDF_Make_Supporter_v1.0.zip
  ├── SDF_Make_Supporter.exe
  ├── Readme.txt (使い方・ライセンス)
  └── sample_images/ (あれば)
  ```
- **メリット**:
  - ユーザーに最初に読んでほしい情報を同梱できる。
  - 一般的なフリーソフトの配布形式として馴染みがある。
  - `settings.json` などが生成されてもフォルダ内に収まり整理しやすい。
- **デメリット**:
  - ユーザーが解凍（展開）する必要がある（Windows標準機能で可能なので障壁は低い）。
- **保守性**:
  - 高い。以下のようなスクリプトでリリース作業も自動化容易。
  ```powershell
  # build_release.ps1 のイメージ
  ./build_exe.ps1
  mkdir release
  cp dist/SDF_Make_Supporter.exe release/
  cp README.md release/
  Compress-Archive -Path release/* -DestinationPath Release_v1.0.zip
  ```

### 3. インストーラー作成 (Inno Setup / NSIS)
`setup.exe` を作成し、`Program Files` にインストールさせる方法です。

- **メリット**:
  - 「インストールした」という安心感がある。
  - スタートメニューやデスクトップにショートカットを自動作成できる。
  - アンインストール機能がつく。
- **デメリット**:
  - **過剰品質**: ファイルコピーで済むツールには大掛かりすぎる。
  - **保守コスト増**: インストーラー作成ツール（Inno Setup等）の独自言語を覚える必要がある。
  - 権限回り（管理者権限など）のトラブルが起きやすい。
- **保守性**:
  - 低め。アプリの更新のたびにインストーラー設定も見直す必要がある。

### 4. Microsoft Store / App Store
- **現状では非推奨**: 審査プロセスやサンドボックス化の対応など、Python製GUIアプリを個人で公開するにはハードルとコスト（登録料など）が見合わない可能性が高いです。

## 推奨される配布フロー (VRChat界隈向け)

今回のターゲットユーザー（VRChatのアバター作者など）を考慮すると、以下の運用が最もスムーズです。

1.  **ビルド**: `build_exe.ps1` でEXE作成。
2.  **パッケージング**: EXEとREADMEをZipにまとめる。
3.  **公開場所**:
    -   **GitHub Releases**: 開発ログとして、また詳しい人向け。
    -   **BOOTH (無料/有料)**: VRChatユーザーが最もアクセスする場所。Zipファイルをアップロードするだけで済む。

### 今後のアクション
現状の `build_exe.ps1` を少し拡張して、**「EXEの生成 → READMEコピー → Zip圧縮」** まで自動で行うようにすれば、リリース作業はワンクリックで完了します。
